### 目录之间的依赖

四个版本共用同一个确定性引擎：`demo/v2-product/corpus.js`。V3 和 V4 都从相对路径 `../v2-product/corpus.js` 引入它。**移动任何一个目录都会打断这个引用**，要动请一起动。

这个 JS 引擎和 `services/api/app/domain/reflection/calculator.py` 实现的是同一套算法，两边必须保持一致——见下。

## 前后端算法一致性

三数问心的算法在两处各实现了一遍：

- 前端 / 原型：`demo/v2-product/corpus.js`
- 后端：`services/api/app/domain/reflection/calculator.py`

```
r1 = (n1 - 1) % 6
r2 = (r1 + n2 - 1) % 6
r3 = (r2 + n3 - 1) % 6
```

**输入范围统一为 1–99**（`three-number-1-99-v1`）。

0 不是合法输入，这一点两边都必须守住，因为两种语言的取模行为不同：

| 输入 | Python `(0-1) % 6` | JavaScript `(0-1) % 6` |
| --- | --- | --- |
| `0` | `5` → 空亡 | `-1` → `PALACES[-1]` = `undefined` |

也就是说，一旦 0 进入系统，后端会给出「空亡」，前端会崩。校验必须挡在入口，而不是依赖某一边的取模恰好没出事。
