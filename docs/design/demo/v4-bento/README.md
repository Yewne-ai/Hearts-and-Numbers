## 色板 v2（2026-08）：为什么重新调色

初版底色 `#F6DF77` 在 OKLCH 里是 `oklch(90% 0.127 97)`——L=90% 这个明度下，C=0.127 已经贴着 sRGB 色域边界，是能取到的最饱和黄。这正是「太亮眼」的直接成因：背景比六宫色（C≈0.02–0.045）浓出 3–7 倍，整页最响的颜色不是内容，是背景本身。

现在的做法：**把底色压回和六宫色同一彩度家族**，只留暖色相。

```css
--bg:  oklch(92.5% 0.048 88)   /* #F4E5C3，原 C=0.127 → 0.048 */
--bg-2: oklch(87%   0.075 86)  /* 强调用：按压态、高亮描边 */
--white: oklch(98.5% 0.012 88) /* 卡片色，和 bg 留 6 个点的明度差，卡片仍"浮"在底色上 */
--ink: oklch(24% 0.015 85)
--dark: oklch(22% 0.014 85)    /* 主入口 / CTA */
```

全部用 OKLCH 指定，同一色相基准（H≈85–88）串起黄底、正文墨色和深色主控件，只有六宫色在 H 上各自散开。所有正文对比度实测复核过（脚本见下方"如何复核"），无一项低于 4.5:1（大字 3:1）。

六宫色也一并调过：

| 宫位 | 色 | 说明 |
| --- | --- | --- |
| 大安 | 蓝 `oklch(90% 0.050 250)` | |
| 留连 | 紫 `oklch(89% 0.055 300)` | |
| 速喜 | 陶橙 `oklch(89% 0.058 53)` | |
| 赤口 | **绿** `oklch(89% 0.070 145)`（摩擦） | 反吉凶映射，§4.6 |
| 小吉 | **粉** `oklch(88% 0.062 345)`（小进展） | 反吉凶映射，§4.6 |
| 空亡 | 近无彩度冷灰 `oklch(90.5% 0.010 245)` | 原先是暖灰，和新底色同色相、同彩度家族，几乎融进背景；改成冷灰蓝，色相和底色拉开，恰好也呼应"空亡=信息不足、空"的含义 |

底色不是奶油白：`C=0.048` 仍是一个可辨认的"颜色"而不是中性色，这是刻意避开 2026 年最饱和的 AI 默认底色（暖中性近白 = cream/sand/paper 那一带）。

**首页不出现任何六宫色**——「可以/先别」两格改用半透白 `--veil`，不再借绿/粉。原因：绿=可以、粉=先别，恰好就是 §4.6 明禁的"绿吉红凶"映射；而且绿在六宫里是赤口（摩擦）、粉是小吉（小进展），同一个颜色在一屏里担两份工，看着就是随机的。规则收紧为一条：**有宫位才有颜色，没宫位就没有**，六宫色只出现在结果页和心事地图。

## 六宫记号（2026-08 新增）

V3（`../v3-yewne/notation.js`）设计了一套六态记号系统：一条线上六种"珠子"状态，三宫连成一行就是这次会话独有的签名，216 种组合对应 216 个可识别的图形。这是判断认为值得跨版本延续的资产——概念比配色更耐用，谁先把这块视觉定义清楚谁占住。

V4 没有照搬那份细线版（V3 是印刷体的重量，配不上便当格 26px 圆角和 800 字重），改用粗描边、可填充的图形语言重新画，并去掉了 V3 的穿线——便当格自己就是容器，不需要再画一条线做归属：

| 宫位 | 记号 |
| --- | --- |
| 大安 | 实心圆 |
| 留连 | 同心双环 |
| 速喜 | 三角 |
| 赤口 | 两根不等高的竖条（错位，不是叉号——叉在界面里读作"错误"） |
| 小吉 | 半填充圆 |
| 空亡 | 虚线空心圆 |

三处使用，权重按场景区分：

- **结果页**：每段左侧 38px 徽记，是整页骨架（详见下方「结果页重构」）
- **Aftercare**：卡片顶部一行三宫签名，独立展示，`--ink-2` 色
- **首页「上次问的那件事」**：24px 徽记，回顾上一次会话的三宫
- **心事地图**：主题卡顶部 24px 徽记

规则：**只在有具体占问结果的地方出现**。通用入口（如"三数问心"格）不放记号，否则会误导用户以为已经有结果了。

## 首页改版（2026-08-12）：从编辑内容换成用户自己的东西

原来首屏三块是「今日一句 / 可以 / 先别」——全是编辑内容，和这个用户没有任何关系。一个主打"长期陪伴、看见反复模式"的产品，最该证明长期价值的位置却对老用户说着和新用户一样的话。

**注意：§4.2 的首页规格只定义了新用户**（一句话定位、典型心事、入口、AI 身份说明），回访用户的首页文档里没写。这是我们自己定的设计决策，不是照文档做。

新的首屏顺序（个人 → 行动 → 浏览 → 氛围）：

```
┌─────────────────────────────┐
│ 上次问的那件事          三天前 │  ← 徽记 + 原话 + 「重看」
├─────────────────────────────┤
│ 三数问心（深色）              │  ← 主入口
├─────────────────────────────┤
│ 心事地图  1 个主题 · 最近三天前 │  ← 真实状态，不是装饰
├─────────────────────────────┤
│ 今日（收小、下移）            │
└─────────────────────────────┘
```

- **「上次问的那件事」**点进去直接打开那次会话的 Aftercare。它和心事地图里"三天前"那条是**同一次会话**（共用 `LAST` 常量），两处不一致 demo 就自相矛盾了。
- **一条红线**：§4.5 原则 6「不以依赖作为留存」+ §1.3 禁止连续签到/等级/命运值。所以没有打卡、没有"你已经 N 天没来"、没有催促。
- 「可以 / 先别」两组文案从首页移除（首屏位置留给个人内容）。是好用的编辑素材，要恢复的话把 `can`/`hold` 数组和对应格子加回来即可。
- 首次用户（无历史）的状态**尚未实现**——demo 恒定展示回访状态，因为长期价值恰恰是静态截图最难体现的。

## 删掉的两处装饰

「心事地图」格下面原有三个相扣的环（本意"攒下的主题"），「三数问心」格下面三个圆点（"要报三个数"）。**设计者本人都读不出三个环是什么意思，就是失败**——它只会让人想到奥运五环或链条。

换成真实数据：`1 个主题 · 最近三天前`。这同时补上了可用性启发式第 1 条（系统状态可见性）——入口要显示里面有没有东西。

## 结果页重构（2026-08-12）

原来是三张大色卡堆叠，四个问题：

1. 三块大面积浅色 = 糖果感，色调提示铺满整卡就过头了
2. 转折文字漂在原底色上，没有容器，像掉出来的
3. 颜色和宫位名在说同一件事，信息冗余、视觉还吵
4. 记号塞在角落当脚注，没有真正"融入"

改成**三段合成一张卡，徽记成为骨架**：

```
┌────────────────────────────────┐
│ (◉)  起势 · 留连                 │  ← 38px 徽记：宫位色块 + 内嵌记号
│      这件事大概已经在你心里转了…   │
│      从「留连」到「空亡」…         │  ← 缩进对齐正文列
│ (◌)  过程 · 空亡                 │
│      ...                        │
│ (●)  当下 · 大安                 │
└────────────────────────────────┘
```

一次改掉四个问题：颜色只留在徽记上（面积极小但位置醒目）；转折文字有了归属；颜色不再和标签重复；记号成为整页骨架而不是脚注。而且三段本来就是一个序列（起势→过程→当下），装在一张卡里读起来是"一次占问"而不是"三条独立事实"。

转折文字**不加左侧竖条**——侧边色条是设计禁项，而且这里本来就不需要，缩进已经说明了归属。

## 徽记组件（.pdot）

`色块 + 内嵌记号` 现在是一个组件，三处复用：结果页（38px）、首页回顾（24px）、心事地图（24px）。

**双通道识别**：颜色 + 形状。色弱用户不必只靠颜色分辨是哪一宫。记号用深墨而不是白色——宫位色都在 L≈90%，白记号在这么浅的底上看不见，深墨实测 11–12:1。

## 接后端（2026-08-16）

结果页的解释不再由本地 `corpus.js` 出，改调 `POST /v1/reflection/reading`。线上和 `/v1` 同源，不涉及跨域。

```
三数 + 心事  →  POST /v1/reflection/reading
                ├─ 200  宫位 + 模型现写的解释（过 verifier.py 校验）
                ├─ 409  场景判不出来 → 让用户从候选里选（§4.5）
                ├─ 422  三数非法（0 / >99 / 非整数）
                └─ 429  限流（6 次/分钟）
```

**宫位和解释是分开的，这一点在界面上要看得出来。** 宫位是纯计算，任何情况下都先算好并显示；缺的只是解释。所以模型挂掉时页面显示的是「解释没能生成 + 重试」，宫位照常在，而不是转圈或者编一段出来——§10.5 要求「展示可重试状态，不伪造结果」。

解释的来源如实标在 colophon 上：

| `generation_mode` | colophon 后缀 |
| --- | --- |
| `llm` | 无（正常情况） |
| `fixed-fallback` | 解释为固定文案（模型未能生成） |
| `local-demo` | 本地演示数据 |

`?local=1` 走本地引擎，给没有后端的场合（本地看稿、断网评审）留的口子，页面会标成 `local-demo`。本地 `corpus.js` 与后端 `calculator.py` 在全部 970,299 种输入上校验过逐点一致（SHA256 相同），但**解释是本地固定文案，不是模型现写的**，所以必须标出来。

从 `#chat` / `#after` / `#map` 直接进来时铺的演示会话同理，也标 `local-demo`。

## 功能对齐（不变）

- 三数：真引擎，`1–99` 滚轮 + 校验，落定后出现心事输入
- 结果：一句总览 + 起势/过程/当下 + 不确定性说明 + 版本 colophon（§10.4）
- Aftercare：核心三项 + 折叠 5 项（§6.4「不超过一屏」）+ 帮助度反馈
- 心事地图：主题卡 + 阶段回看（§6.5 需累积三次）
- 首页 AI 身份说明常驻（§4.2、§8.10）

## 如何复核对比度 / 色域

新色板全部用 Node 手写的 OKLCH↔sRGB 转换脚本核对过（标准矩阵，非近似），检查项：

1. 六个新增色是否在 sRGB 色域内（避免浏览器裁切成非预期颜色）
2. 每一处正文色在其实际背景（含半透明 `--veil` 叠加后的合成色）上是否达 WCAG AA（正文 4.5:1，大字/粗体 3:1）
3. 六宫色两两之间、以及六宫色与新底色之间的可分辨度（欧氏距离）

若以后要再调色，建议照这个流程走一遍，不要只用肉眼判断——`--ink-3` 曾经两次因为"看着还行"实际测出来只有 2.9–3.3:1。
