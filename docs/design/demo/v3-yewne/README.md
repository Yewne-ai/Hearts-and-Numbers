# 于你 Yewne — Demo V3

**于你自己的设计方向。**四屏做深，不求覆盖全流程。

## 打开方式

用了 ES module，**必须通过 http 打开**。

```bash
cd demo && python3 -m http.server 5173
```

- V3：`http://localhost:5173/v3-yewne/`
- 六宫记号规范：`http://localhost:5173/v3-yewne/sheet.html`

直达：`#read` / `#after` / `#map`（会预填 `2·5·2`）。

## 设计立场

参照 Co-Star 的 **register**——用临床的、精确的方式呈现本质上不精确的内容——但换掉全部表皮：

| Co-Star | 于你 V3 | 为什么 |
| --- | --- | --- |
| 纯黑底 | 冷近白 | 文档 §4.6 要求明亮；黑底离「传统算命网站」太近 |
| 西方超现实拼贴 | 六宫记号系统 | 希腊胸像和铜版画是别人的文化语言，搬过来就是模仿 |
| 刻薄断言的文案 | 克制但不冷 | Co-Star 对结果不负责；于你有 Aftercare、安全流、紧急联系人，**它是要负责的**。用户里有 S1–S2 的人 |
| 身份叙事（你是什么样的人） | 处境叙事（这一件事，此刻） | §6.4 §6.5 禁止人格标签与命运标签 |

**没有借爻卦。** 阴阳爻的断线实线很诱人，但文档 §5.1 承诺不混入六爻或其他体系，视觉上引入等于把易经偷偷带进来。

## 色彩策略：温差即功能差

**主界面全墨，零彩色。颜色只出现在「你带走的东西」上。**

- 冷白 `#F4F5F6` = 在分析、在理清（三数、结果页）
- 宣纸 `#ECE8DB` = 这是你可以拿走的（Aftercare 卡、心事地图主题卡）

Aftercare 页的反馈按钮和操作**故意留在冷白上、卡片之外**——纸上是你的内容，冷白是系统。

宣纸色不是米黄：明度压低一档、彩度只留一点、色相往黄绿而不是橙黄。真实生宣偏灰，大家印象里那个暖金色是做旧仿古纸。

**不做纸纹理。** 屏幕上的纸纹几乎都会翻车，噪点读起来廉价还吃正文对比度。纸感来自颜色、内缩留边、和卡内的印刷逻辑。

## 六宫记号系统（`notation.js`）

Co-Star 的行星符号成立靠三条：**继承来的**、**同源构成的**、**当字排而不是当图标**。

小六壬六宫没有既有符号，所以第一条拿不到——但文档 §1.4 已明确对外称「Yewne 六宫三数法 v1」，是自己的产品算法、不冒认流派正统。既然如此，**发明一套明显属于于你的记号是诚实的**，而且这块视觉在市场上是空的。

全部由「一条基准横线 + 圆的一种状态」生成。横线 = 你正在经历的这件事，圆的形态 = 此刻的状态：

| 记号 | 宫位 | 含义 |
| --- | --- | --- |
| ─●─ | 大安 | 实心，落定 |
| ─◎─ | 留连 | 绕了一圈回到原处 |
| ─▶─ | 速喜 | 有方向，往前 |
| ─┴┬─ | 赤口 | 两笔错开，不在一条线上 |
| ─◐─ | 小吉 | 开了一半 |
| ─○─ | 空亡 | 空的，**且基准线断开** |

**「空亡」的断线是记号里唯一携带语义的破例**——信息不足、悬置，线就是断的。

设计约束：

- **不做吉凶编码**。「赤口」用错位而不是叉号——叉在界面里读作「错误」，那就是吉凶语义
- **笔重对齐汉字**。汉字密而重，所以比 Co-Star 的发丝级行星符号实一档，否则行内混排会显虚
- 纸上用色刻意保持反吉凶映射：**绿给赤口（摩擦），红给小吉（小进展）**，满足 §4.6「不把红色等同于凶、绿色等同于吉」

### 会话签名

三宫记号首尾相接成一条连续记谱：

```
─◎──○──●─     留连 · 空亡 · 大安
```

它贯穿 **结果页 → Aftercare 卡 → 心事地图**。216 种组合就是 216 个视觉签名，用户翻地图时能认出某一次。

## 四屏

| 屏 | 说明 |
| --- | --- |
| **三数** | 全产品唯一有仪式感的时刻，没有先例可借。填空线而不是输入框，`1–6` 是印刷刻度而不是键盘。三数落定时一条线横贯——「合」的瞬间。10 秒内完成（§5.2） |
| **结果** | 先一句核心判断，再展开三段（§5.10）。位置名 / 记号 / 宫位名的数据行是 Co-Star 那张表的直接转译。页脚有 colophon：三数 + `method_version` + `corpus_version`（§10.4） |
| **Aftercare** | 宣纸卡。核心三项直出，其余 5 项折叠（§6.4「不超过一屏」）。顶部是带色的会话签名 |
| **心事地图** | Co-Star 的细线表格就是原型：一行一个主题，跟着它的记号。阶段回看需要至少三次记录（§6.5） |

深聊、心事输入、记忆确认、安全流不在本版——V2 已覆盖主闭环，V3 的价值在设计深度不在覆盖度。

**没有底部 tab 栏，这是刻意的**：这四屏是一条序列，不是一个 hub。

## 排版

- 标题 **宋体**（Georgia 出拉丁 / Songti SC 出汉字）。文化重量来自书和报纸，不是符咒和签文——正好卡在 §4.6 想要的位置
- 正文系统无衬线，元数据等宽 + 字距
- 印刷逻辑：固定页边距、发丝细线分区、**零阴影、零圆角**、大量真实留白
- 主操作是**带下划线的文字链接**，不是填色按钮

Web 中文宋体太重（思源宋体好几 MB），demo 走系统字体栈，真上线再做子集化。

## 算法

`import { buildReading } from '../v2-product/corpus.js'` —— **同一个引擎，两套呈现**。

这不是偷懒，是文档 §0.1「三数结果由确定性引擎计算，任何大模型均无权修改」的演示：换一整套视觉，结果一个字都不变。

## 已知的坑（改的时候注意）

**中文之间不能在 HTML 里换行。** 换行会被折叠成一个空格，在中文里就是个错别字。多行中文正文必须写成一行。已有自动检查脚本覆盖这一项。
